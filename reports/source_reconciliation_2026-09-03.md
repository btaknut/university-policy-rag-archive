P0 처리 순서:

1. 공식 상세 페이지에서 첨부 원본을 다운로드한다.
2. 원본 SHA-256을 계산해 동일 바이트가 이미 있는지 먼저 확인한다.

## 5. 과거 버전 백필 및 정규화 검토(P1/P2)

### 산학협력단 규정

공식 사이트의 82개 공포 버전 중 20개만 기존 manifest에서 제목+공포일이 일치했다.

- 제목 그룹은 있으나 해당 공포일 버전 없음: 52개
- 제목 그룹 자체 미연결: 10개
  - 산학협력단 정관 7개
  - 생명윤리심의위원회 규정 1개
  - 등록연구소설치운영에관한규정 2개

이는 최근 누락이 아니라 산학협력단 전용 원천의 과거 파일을 별도로 수집하지 않은 데서 생긴 것으로 보인다. 원문 파일 해시를 확인하기 전에는 62개를 확정 누락으로 자동 반영하지 않는다.

### 교통대 지침

제목 정규화 후에도 연결되지 않은 게시물 3개:

1. 충주생활관 숙박시설관리 운영지침(24.1.11., 지침 제516호),(게스트룸 관비수정) — 게시 2025-11-12
2. 고시원 운영 지침 일부개정안(2019.12.30. 지침 제240호) — 게시 2020-01-14
3. 사회봉사활동 학점 인정 지침 일부개정안(2019.8.29. 지침 제220호) — 게시 2019-08-30

파일 해시와 실제 문서 표제를 확인해 신규 그룹, 기존 그룹 별칭, 단순 게시물 오기 중 하나로 판정한다.

### 산학협력단 지침

전체 85개 중 제목+일자 일치 20개, 제목 그룹만 연결 40개, 제목 그룹 미연결 25개다. 이 원천에는 "규정" 표제 파일도 포함되어 있어 `document_type`만으로 대조하면 누락이 발생한다. 실제로 "생물안전관리 규정(2024.12.31.)"은 지침 원천에 게시되어 있으나 저장소에서는 `regulation`으로 연결된다.

따라서 원천 분류(`source_id`)와 문서 유형(`document_type`)을 분리해야 한다.

## 6. 수집기 구현 요구사항(P1)

4개 커넥터를 독립적으로 둔다.

- `ut_regulations`: 8개 범주와 페이지를 순회하고 `register` 상세 이력을 수집
- `ut_guidelines`: 목록 → 상세 → 모든 첨부파일 수집
- `sanhak_regulations`: 그룹별 파일명, 공포일, 다운로드 URL 수집
- `sanhak_guidelines`: 페이지 → 상세 → 모든 첨부파일 수집

공통 레코드에는 최소한 아래 필드를 둔다.

- `source_id`, `source_record_id`, `source_group`
- `source_page_url`, `attachment_url`, `attachment_filename`
- `posted_date`, `effective_date`
- `title_raw`, `title_normalized`, `department`
- `sha256`, `retrieved_at`, `http_etag`, `last_modified`

중복 판정 우선순위:

1. 원본 파일 SHA-256 동일
2. 공식 원천 고유 ID 또는 첨부 ID 동일
3. 정규화 제목 + 시행일 동일
4. 제목 유사도만 일치하면 자동 병합하지 않고 검토 큐로 보냄

## 7. 자동화 운영안

- GitHub Actions에서 수동 실행(`workflow_dispatch`)과 주 1회 점검(`schedule`)을 제공
- 수집 단계와 manifest 반영 단계를 분리
- 변경이 없으면 종료
- 변경이 있으면 보고서와 PR을 생성하되 자동 병합 금지
- 삭제/폐지 감지는 즉시 삭제하지 않고 상태 전이 후보로 기록
- 원천별 실패를 격리하고, 한 원천의 오류가 다른 원천 수집을 막지 않게 구성
- URL, 첨부 해시, 문서 수, 버전 수, current 버전 단일성 검증을 CI에 추가
