# 보안 및 공개범위 검토

## 자동 점검 결과

- 정규화 가능 원문에서 주민등록번호, 개인 휴대전화, 외부 개인 이메일, 대표 API 키/토큰, 비밀번호 할당, 사설 IPv4 패턴 후보: 0건
- `.env`는 Git 제외, `.env.example`은 변수명만 포함한다.
- 100MB 이상 파일: 0건
- 보안 후보가 발생하면 파일을 자동 삭제하지 않고 `sources/restricted_manifest`, `metadata/excluded_files.csv`에 해시·사유만 기록하도록 구현했다.
- restricted/review_required 문서는 정규화와 청크 생성 대상에서 제외되며 검증기가 이를 확인한다.

## 한계와 수동 검토

HWP 847건을 PDF로 변환한 뒤 새 Markdown을 포함한 전체 정규화 코퍼스를 다시 검사했다. 다음 후보는 문맥 검토 결과 실제 개인정보가 아닌 공개 서식·지원 정보로 확인했다.

- `123456-1234567`: `교육공무원 복무처리 요령` 서식의 월·일이 성립하지 않는 주민번호 자리표시자
- `010-0101-0101`: 같은 서식의 예시 연락처
- `koreasales@turnitin.com`: 연구검증 절차에 명시된 Turnitin Korea 공개 지원 주소 3건
- 휴대전화 후보 3건: YAML front matter의 SHA-256 문자열을 선택적 구분자 정규식이 오탐한 것으로 확인하여 탐지식을 구분자 필수로 보정

실제 주민등록번호, 개인 휴대전화, 개인 이메일 또는 비밀 키는 발견되지 않았다. 다만 이미지 서명·도장, 표 안의 비정형 개인정보, 계좌번호, 채용·학생·교직원 개인정보 여부는 사람이 표본 및 위험기반으로 계속 확인해야 한다. 저장소를 public으로 전환해서는 안 된다.
